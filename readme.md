# bolid-c2000pp — С2000-ПП (Болид) в Python и Home Assistant

Асинхронная библиотека на Python и интеграция для Home Assistant для работы с преобразователем протокола
**«С2000-ПП»** (АО НВП «Болид», система «Орион») через конвертер **С2000-Ethernet** (Modbus-RTU поверх UDP).

Позволяет читать состояния шлейфов (зон) охранно-пожарной сигнализации, брать их на охрану и снимать,
управлять реле, читать журнал событий — из своих скриптов, SCADA-систем и умного дома.

> **Неофициальный проект.** Не связан с АО НВП «Болид». Основан на руководстве по эксплуатации
> АЦДР.426469.020 РЭп и на разборе реального обмена. Подробный разбор протокола — в [`agents.md`](agents.md).

## Возможности

| | |
|---|---|
| **Мониторинг зон** | опрос до 512 зон по расписанию, расшифровка состояний по таблице РЭ (≈158 кодов с приоритетами) |
| **Управление** | взять/снять зону или раздел, включить/выключить реле |
| **Журнал событий** | чтение журнала ПП (обрыв, пожар, тревога, взятие/снятие с номером пользователя, …) |
| **Надёжный обмен** | один запрос «в полёте», строгая проверка каждого ответа (адрес, функция, форма, CRC, источник), карантин после таймаута — запоздавший ответ не попадёт в соседнюю зону |
| **Группы зон** | соседние зоны читаются одним запросом; зоны без данных изолируются и не мешают остальным |
| **Подтверждение команд** | после команды «взять/снять» состояние показывается целевым, пока ПП не подтвердит (без «моргания» в интерфейсе) |
| **Несколько клиентов** | конвертер рассылает ответы всем адресам из своего списка — клиент распознаёт чужие команды взять/снять и обновляет нужную зону |
| **Контроль связи** | таймаут устаревания данных на зону, флаг доступности, статистика обмена и задержек |
| **Диагностика** | утилита замера скоростей, декодер захватов `tcpdump`, режим подробного лога |
| **Home Assistant** | сенсоры зон, переключатели охраны, сущность связи, события на шине HA |

Только стандартная библиотека Python (≥ 3.9), asyncio.

## Как это работает

```
приборы «Орион» ──RS-485── С2000-ПП ──RS-485 (Modbus-RTU)── С2000-Ethernet ──UDP── ваш компьютер / Home Assistant
```

* С2000-Ethernet работает как прозрачный шлюз: Modbus-RTU кадр упаковывается в UDP-датаграмму с
  коротким заголовком `10 LEN CNT CNT FLAG`.
* Ответы конвертер шлёт **на фиксированный порт (по умолчанию 40002)** и **каждому адресу из своего
  списка удалённых устройств**. Поэтому клиент слушает локальный UDP-порт 40002 и видит и свои ответы,
  и ответы на запросы других клиентов.
* Modbus-шина одна: запросы идут **строго по очереди**. В ответе нет номера запроса, поэтому каждый
  ответ проверяется на соответствие ожидаемому запросу.
* Клиент одновременно ведёт опрос по расписанию, слушает порт и выполняет команды (команды идут вне
  очереди опроса, с более высоким приоритетом).

## Быстрый старт

**Требуется:** С2000-ПП версии 3.xx (проверено на 3.01 в режиме «Орион-Slave» с пультом С2000М 4.x),
конвертер С2000-Ethernet (проверено на 2.77), Python 3.9+.

1. Настройте конвертер (см. [Настройка оборудования](#настройка-оборудования)) — главное, чтобы адрес
   вашего компьютера был в списке удалённых устройств конвертера.
2. Скопируйте `c2000pp.py` в свой проект (отдельной установки нет).
3. Проверьте связь:

```bash
python c2000pp.py 192.168.1.50 info
python c2000pp.py 192.168.1.50 zones --zones 1-16
```

Пример вывода `zones`:

```
   1  ok         24  Взятие входа на охрану
   2  ok        109  Снятие входа с охраны
   3  no_data     0  Нет состояния  Modbus exception 3 (недопустимое значение ...)
```

## Настройка оборудования

### С2000-Ethernet (Uprog)

Ниже — рабочая конфигурация. Адреса в примере условные: конвертер `192.168.1.50`, компьютер с
библиотекой или Home Assistant `192.168.1.10`.

**Вкладка «Ethernet»**

| Параметр | Значение |
|---|---|
| UDP-порт отправителя | **40002** (порт, с которого конвертер шлёт ответы; клиент слушает его же) |
| Использовать один UDP-порт на чтение/запись | включено |
| Список удалённых устройств, строка 1 | IP вашего компьютера/HA `192.168.1.10`, UDP-порт получателя **40002**, тип порта «статический», совместимость «C2000-Ethernet (авто)» |
| Остальные строки списка | `0.0.0.0` |
| Контроль соединения | по умолчанию (период 10 с, нарушение 30 с, разрыв 120 с) |

**Вкладка «RS-485/232»** (сторона С2000-ПП)

| Параметр | Значение |
|---|---|
| Режим работы | **Прозрачный** |
| Тип интерфейса | RS485 |
| Скорость обмена | должна совпадать с Modbus-настройкой С2000-ПП (например 115200) |
| Тип протокола | «Другой» |
| Количество стоп-бит | как в С2000-ПП (например 1) |

### С2000-ПП

Настройка — программой Uprog (страница «Прибор»):

* тип интерфейса интеграции **Modbus RS-485**, скорость, контроль чётности и стоп-биты — те же, что у конвертера;
* **адрес прибора на интерфейсе Modbus** — это параметр `slave_id` библиотеки (по умолчанию 1);
* для команд взять/снять включите **«Управление состоянием зон, разделов, реле по Modbus разрешено»**;
* в таблице зон заведите нужные шлейфы (тип зоны 1 — состояние ШС); соседние номера зон читаются
  одним запросом;
* не включайте «Прямую трансляцию событий» — она нарушает чтение состояний зон.

> **Два разных адреса.** В Uprog прибор виден с *Орион-адресом* (адрес на шине «Орион»), а в
> Modbus-запросах используется *Modbus-адрес*. Это разные адресные пространства.

### Важные особенности

* **Адрес клиента обязан быть в списке удалённых устройств конвертера** — иначе ответы до него не дойдут.
  Для временных тестов с другого компьютера добавьте его IP во вторую строку списка.
* Один UDP-порт 40002 не может слушать несколько процессов на одной машине (интеграция HA, скрипт,
  утилита bench) — ответы достанутся только одному. Останавливайте лишнее.
* Раз в ~10 с конвертер шлёт каждому адресу из списка собственный служебный пакет (10 байт, не Modbus).
  Библиотека учитывает его отдельно и не считает ошибкой.
* На скорости 115200 время передачи по линии пренебрежимо; основное время «запрос → ответ» уходит на
  обработку в ПП и конвертере. Режим упаковки данных в конвертере (признаки паузы/тайм-аута) можно
  настраивать, сравнивая задержки утилитой [bench](#замер-скоростей-bench).

## Библиотека: примеры

Все примеры — `asyncio`. Конвертер `192.168.1.50`, порт 40002.

### 1. Разовый опрос

```python
import asyncio
from c2000pp import C2000PP

async def main():
    pp = C2000PP("192.168.1.50", 40002, zones=range(1, 17))
    await pp.t.start()                      # только сокет, фоновый опрос не нужен
    try:
        print(await pp.read_device_info())  # {'type': 36, 'version': '3.01', 'mode': 'slave', ...}
        await pp.poll_all()                 # один цикл опроса всех зон
        for n, z in pp.zones.items():
            print(n, z.status, z.code, z.name, "ВЗЯТА" if z.armed else "снята")
    finally:
        await pp.stop()

asyncio.run(main())
```

### 2. Постоянный мониторинг с подписчиком

```python
import asyncio
from c2000pp import C2000PP

def on_event(name, payload):
    if name == "zones":                       # payload: множество номеров изменившихся зон
        for n in sorted(payload):
            z = pp.zones[n]
            print(f"зона {n}: {z.name} [{z.status}] armed={z.armed}")
    elif name == "availability":              # True/False: есть ли связь
        print("связь:", "есть" if payload else "ПОТЕРЯНА")
    elif name == "foreign_command":           # другой клиент взял/снял зону
        print("чужая команда:", payload)      # {'zone': 2, 'code': 24}

async def main():
    global pp
    pp = C2000PP("192.168.1.50", zones=range(1, 21), poll_interval=10, stale_timeout=40)
    pp.add_listener(on_event)
    async with pp:                            # start() / stop()
        await asyncio.sleep(3600)

asyncio.run(main())
```

События подписчика:

| Событие | payload |
|---|---|
| `zones` | множество номеров зон, у которых изменилось состояние/статус |
| `availability` | `True`/`False` — появилась/пропала связь |
| `poll` | итог цикла опроса: `ok`, `changed`, `aborted`, `duration` |
| `foreign` | чужой валидный ответ на запрос чтения (`Frame`) |
| `foreign_command` | чужая команда зоне: `{'zone': N, 'code': K}` |
| `event` | событие журнала (`PPEvent`, только при `use_events=True`) |

Колбэки вызываются в потоке event loop; не блокируйте их.

### 3. Взять и снять шлейф

```python
async with C2000PP("192.168.1.50", zones=[1, 6]) as pp:
    ok = await pp.set_armed(1, True, wait=10)        # команда + ожидание подтверждения до 10 с
    print("взят" if ok else "не подтвердился", pp.zones[1].name)

    await pp.arm_zone(6)                             # без ожидания
    print(pp.zones[6].armed, pp.zones[6].pending)    # True True — ждём подтверждения (целевое)
    await asyncio.sleep(4)
    print(pp.zones[6].armed_actual, pp.zones[6].name)  # реальное состояние

    await pp.disarm_zone(6)
    await pp.arm_section(1)                          # раздел целиком
```

* `ZoneData.armed` — *эффективное* состояние: целевое, пока идёт подтверждение, потом реальное.
* `ZoneData.armed_actual` — только то, что сообщил ПП.
* «Взята» — код 24 или 23 (задержка взятия). После взятия состояние обычно меняется с задержкой
  1–3 с, у шлейфов с задержкой взятия — дольше.
* Пожарный шлейф после снятия может показывать код 112 «Отключение ШС», а не 109 — это нормально.
* Команда может завершиться ошибкой: `ModbusException` (например, код 4 — нет связи с прибором
  или управление запрещено в конфигурации ПП) или `C2000Timeout`. Ожидание подтверждения при этом снимается.

pp = C2000PP("192.168.1.50", zones=range(1, 21), use_events=True, event_interval=2.0)

### 6. Запись изменений в CSV

```python
import asyncio, csv, time
from c2000pp import C2000PP

async def main():
    pp = C2000PP("192.168.1.50", zones=range(1, 33), poll_interval=5)
    with open("zones.csv", "a", newline="", encoding="utf-8") as f:
        w = csv.writer(f)
        def on_change(name, payload):
            if name == "zones":
                for n in sorted(payload):
                    z = pp.zones[n]
                    w.writerow([time.strftime("%F %T"), n, z.code, z.name, z.status])
                f.flush()
        pp.add_listener(on_change)
        async with pp:
            await asyncio.sleep(24 * 3600)

asyncio.run(main())
```

### 8. Использование из обычного (не async) кода

```python
import asyncio
from c2000pp import C2000PP

def read_states(host, zones):
    async def run():
        pp = C2000PP(host, zones=zones)
        await pp.t.start()
        try:
            await pp.poll_all()
            return {n: (z.code, z.name) for n, z in pp.zones.items()}
        finally:
            await pp.stop()
    return asyncio.run(run())

print(read_states("192.168.1.50", range(1, 9)))
```

### 9. Низкоуровневые запросы Modbus

```python
regs = await pp.t.read_holding(40000, 8)      # состояния зон 1..8 (8 регистров)
bits = await pp.t.read_discrete(8, 4)         # режим, связь с мастером, тампер, питание
await pp.t.write_register(40000, 24)          # зона 1 ← «взять»
print(pp.t.stats)                             # счётчики обмена
print(pp.t.rtt_stats())                       # задержки запрос→ответ, мс
```

Режим отладки — прослушка всех датаграмм:

```python
pp.t.tap = lambda direction, ts, data, addr: print(direction, addr, data.hex(" "))
```

### Статусы зоны (`ZoneData.status`)

| Статус | Значение |
|---|---|
| `ok` | свежие данные |
| `pending` | данные ещё ни разу не получены |
| `no_data` | ПП отвечает ошибкой (зоны нет в базе ПП или данных ещё нет); перечитывается раз в 60 с |
| `timeout` | давно не обновлялась (`stale_timeout`) |

### Параметры `C2000PP(...)`

| Параметр | По умолч. | Описание |
|---|---|---|
| `host`, `port` | —, 40002 | адрес и UDP-порт конвертера |
| `slave_id` | 1 | Modbus-адрес С2000-ПП |
| `zones` | `()` | номера зон 1…512 |
| `poll_interval` | 10 | период опроса, с (допустимо от 1) |
| `stale_timeout` | `max(3×poll+5, 30)` | через сколько секунд без обновления зона получает статус `timeout`; если ≤ периода — автоматически увеличивается |
| `group_size` | 8 | зон в одном запросе (1…100) |
| `use_events` | `False` | читать журнал ПП (разрушающе) |
| `event_interval` | 2 | период проверки журнала, с |
| `refresh_on_foreign` | `True` | реагировать на чужие ответы и команды |
| `pending_timeout` | 15 | сколько ждать подтверждения команды, с |
| `local_port` | = `port` | локальный UDP-порт (ответы приходят на него) |
| `timeout`, `retries` | 1.5, 2 | ожидание ответа на один запрос, с / число повторов при таймауте |
| `gap` | 0.02 | пауза между запросами, с |
| `quarantine` | 0.4 | после таймаута отбрасывать запоздавшие ответы, с |

## Замер скоростей (bench)

`bench_c2000pp.py` измеряет, как быстро отвечает ваша установка, и подсказывает параметры опроса.
Запускайте на машине, чей адрес прописан в конвертере, остановив остальные программы, слушающие порт 40002.
Утилита непрерывно слушает порт и пишет **каждую** датаграмму в `bench_<время>.log`, итоги — в `.json`.

```bash
# безопасно (ничего не пишет в ПП): прослушивание, задержки, группы, стресс, события
python bench_c2000pp.py 192.168.1.50 --zones 1-64

# переключение шлейфа: команда → таймлайн состояния → обратная команда; 2 цикла
python bench_c2000pp.py 192.168.1.50 --zones 1-64 --phases switch --allow-write --test-zone 1

# ожидание событий журнала (разрушающее чтение)
python bench_c2000pp.py 192.168.1.50 --zones 1-16 --phases watch --allow-write --watch 180

# самопроверка утилиты на встроенном эмуляторе, без оборудования
python bench_c2000pp.py --sim
```

| Фаза | Что делает | Результат |
|---|---|---|
| `listen` | N секунд ничего не шлёт | кто ещё опрашивает, период служебных пакетов, интервалы чужих ответов |
| `info` | тип/версия/режим/лимиты ПП | |
| `single` | серия чтений одной зоны | задержка min/avg/p50/p95/max |
| `groups` | группы 1…64 зон | задержка по размеру группы, **оценка цикла для 16…512 зон**, рекомендация периода |
| `stress` | запросы подряд при паузе 0…50 мс | потери и запросов/с → допустимая `gap` |
| `events` | чтение счётчика непрочитанных событий | задержка (журнал не затрагивается) |
| `watch` | ждёт события и логирует их | события с кодом, зоной, временем ПП и состоянием зоны; **разрушающая**, нужен `--allow-write` |
| `switch` | команда → состояние каждые 0.25 с → обратная команда | время эха, первого изменения, подтверждения, число «морганий»; шлейф возвращается в исходное состояние |

Задержки считаются «чистыми» — от отправки до валидного ответа, без очереди и паузы между запросами.

### Расшифровка захвата трафика

```bash
tcpdump -i any host 192.168.1.50 -s 0 -w /tmp/capture.pcap
python pcap_decode.py /tmp/capture.pcap --from 192.168.1.50 --to 192.168.1.10
```

Понимает Ethernet, Linux cooked (SLL, SLL2); сворачивает дубли, которые даёт `-i any`; печатает
запросы, ответы, адреса регистров, значения и названия состояний.

## Интеграция Home Assistant

Установка: скопируйте папку `custom_components/bolid` в `config/custom_components/`, перезапустите
Home Assistant, затем «Настройки → Устройства и службы → Добавить интеграцию → Bolid S2000PP».

### Сущности

| Сущность | Что | Примечание |
|---|---|---|
| `sensor` «Шлейф N» | состояние зоны (текст) + атрибуты `code`, `status`, `armed`, `error` | при статусе `timeout` — «недоступен» |
| `switch` «Охрана шлейфа N» | взять/снять | по умолчанию отключены — включите нужные; не «моргают»: до подтверждения показывается целевое состояние |
| `binary_sensor` «С2000-ПП связь» | есть ли валидные ответы | диагностическая; в атрибутах счётчики обмена, задержки, длительность цикла опроса |

### Настройки (при добавлении и в «Настроить»)

| Параметр | Ограничения | Описание |
|---|---|---|
| Зоны | `1-20, 25` | какие зоны создавать и опрашивать |
| Период полного опроса, с | 1…3600 | период опроса всех зон |
| Таймаут устаревания, с | 2…7200, **строго больше периода** | рекомендуется ≥ 3× периода |
| Зон в одном запросе | 1…100 (по умолчанию 8) | больше — быстрее на сотнях зон; проверяйте утилитой bench |
| Читать журнал событий | выкл. | см. ниже |
| Создать переключатели | вкл. | |

При смене настроек интеграция перезагружается; порт 40002 освобождается корректно.

### Журнал событий

С2000-ПП хранит журнал на 256 записей (кольцевой): «Пожар», «Тревога», «Взятие/снятие» с номером
пользователя, «Авария сети 220 В», «Потеря связи с прибором», изменение реле и т. д. Опрос состояний
показывает только *текущее* состояние; журнал сообщает, *что происходило*. ПП события не «присылает»:
их нужно читать запросами.

Включение опции «Читать журнал событий» даёт:

1. События `bolid_event` на шине Home Assistant с полями `host, number, code, name, zone, section,
   user, time` — для автоматизаций;
2. быстрое обновление: при событии по зоне она перечитывается сразу, а не ждёт периода опроса;
3. короткие срабатывания между опросами не теряются.

Ограничения:

* Чтение **разрушающее**: событие, прочитанное одним клиентом, пропадает для остальных. Если журналом
  пользуется ещё одна система, включайте опцию только в одном месте. Состояния зон от этого не страдают.
* Нагрузка: один запрос каждые 2 с плюс по два запроса на каждое событие.
* Не включайте в конфигурации ПП «Прямую трансляцию событий».

Пример автоматизации:

```yaml
trigger:
  - platform: event
    event_type: bolid_event
    event_data: { code: 37 }          # 37 = «Пожар»
action:
  - service: notify.notify
    data: { message: "Пожар, шлейф {{ trigger.event.data.zone }} ({{ trigger.event.data.time }})" }
```

### Несколько клиентов одновременно

Конвертер присылает ответы **всем** адресам из своего списка, поэтому интеграция видит и то, что
запросил другой клиент (например, SCADA или скрипт):

* чужая **команда** взять/снять распознаётся точно (в ответе есть адрес и значение) — переключатель
  зоны сразу показывает целевое состояние, зона перечитывается быстрыми шагами;
* чужой **запрос чтения** (в ответе нет адреса регистра) приводит к внеплановому опросу всех зон,
  не чаще раза в 3 секунды.

Ограничение: пока клиент ждёт собственный ответ, чужой ответ той же формы может быть принят за свой;
данные исправятся ближайшим внеплановым опросом. Для строгости опрашивать должен один клиент.

## Подбор параметров опроса

Ориентировочные оценки (одиночное чтение ≈ 40–70 мс, пауза между запросами 20 мс). **Измерьте свою
установку утилитой bench** — реальные цифры зависят от ПП, конвертера и режима работы ПП.

| Зон | Цикл, группа 8 | Цикл, группа 32 | Разумный период |
|---|---|---|---|
| 16 | ~0.2 с | ~0.1 с | 1–2 с |
| 64 | ~0.6 с | ~0.2 с | 2 с / 1 с |
| 128 | ~1.3 с | ~0.4 с | 3–5 с / 1–2 с |
| 256 | ~2.6 с | ~0.7 с | 6–10 с / 2 с |
| 512 | ~5 с | ~1.4 с | 10 с / 3–4 с |

Правила: период ≥ 2 × цикла опроса; таймаут устаревания > периода (лучше ≥ 3×). Большие группы
быстрее, но если в группе есть зона без данных, ПП отвечает ошибкой, и группа разбивается на одиночные
запросы (зона изолируется в статус `no_data`). Если цикл опроса дольше периода, в лог пишется
предупреждение. При недоступном ПП цикл прерывается после первой группы, исчерпавшей повторы, —
он не растягивается на минуты даже при 512 зонах.

Задержка подтверждения команды взять/снять (1–3 с и более) **не зависит** от периода опроса.

## Ограничения и безопасность

* Проект **не сертифицирован** и не предназначен для функций, от которых зависит безопасность людей
  (пожарная автоматика, оповещение, эвакуация). Используйте его для мониторинга, учёта и
  автоматизации поверх штатной системы, а не вместо неё.
* Команды взять/снять и управление реле выполняются на реальном оборудовании — проверяйте на тестовых
  шлейфах и учитывайте последствия (ложные тревоги, запуск исполнительных устройств).
* Не реализовано: числовые значения (температура, влажность, CO, счётчики, РИП), синхронизация
  времени ПП, упрощённый режим чтения (INPUT-регистры v3.xx). Протокол ПП в других режимах работы
  (например «Орион-Master») проверялся меньше.
* Используйте на доверенной сети: протокол Modbus/UDP не имеет аутентификации.

## Диагностика

| Симптом | Причина / действие |
|---|---|
| `Address in use`, интеграция «не готова» | порт 40002 занят другим процессом (вторая копия интеграции, скрипт, bench, SCADA). Закройте его |
| все зоны `timeout`, связь выкл. | нет ответов: проверьте IP конвертера, что адрес клиента прописан в списке удалённых устройств, UDP-порт, `slave_id`, скорость и чётность |
| `bad_frames` растёт | битые кадры (CRC/длина); смотрите лог с `-v`; проверьте настройки упаковки данных в конвертере |
| `unmatched` растёт | приходят ответы на чужие запросы или запоздавшие; при нескольких адресах в списке конвертера это норма |
| `lost_by_counter` растёт | теряются UDP-ответы конвертера |
| зона `no_data` | ПП отвечает ошибкой 3: зоны нет в базе ПП или данных ещё нет |
| состояние всё время «Восстановлена связь с прибором» (251) | ПП ещё не знает реального состояния (режим Slave: мастер не передал) |
| команда → `exception 4` | нет связи с прибором или управление зонами запрещено в конфигурации ПП |
| шлейф взят, но вернулся | «Неудачное взятие» (17): шлейф нарушен в момент взятия |

Для разбора проблем: `python c2000pp.py <host> monitor -v`, `bench_c2000pp.py` (лог каждой датаграммы)
и `pcap_decode.py`. Описание протокола и типичных ловушек — в [`agents.md`](agents.md).
